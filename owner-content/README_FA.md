# آرشیو دائمی محتوای مالک برای نسخه‌های بعدی بازار

بخش‌های موردنظر: «دیدن خدا در زندگی» (`see_god`) و «کلیپ‌های تصویری» (`videos`).

۱. مدیر در پنل واقعی Cloudflare مطلب را منتشر می‌کند؛ مطلب بلافاصله در Cloudflare ذخیره می‌شود.
۲. GitHub Actions طبق زمان‌بندی حدوداً هر نیم‌ساعت (ممکن است با تأخیر اجرا شود) یا با اجرای دستی `Archive owner sessions and clips from Cloudflare to GitHub`، فهرست عمومی `/api/manifest` و کاورهای مرتبط را می‌خواند.
۳. هر مطلب در `owner-content/items/<id>.json` و تصویر آن با SHA-256 در `owner-content/media/` نگهداری می‌شود. فهرست و هش‌ها در `latest.json` و نمای نسخه‌ای غیرقابل‌تغییر در `revisions/` ذخیره می‌شوند.
۴. حذف یک مطلب از پنل Cloudflare، فایل تاریخی آن را از GitHub حذف نمی‌کند؛ فقط فهرست فعال در بازبینی جدید تغییر می‌کند.
۵. هنگام آماده‌سازی نسخه جدید بازار، `Build future marketplace update with archived owner content (unsigned)` را دستی اجرا کنید. خروجی از محتواهای فعال آرشیو و سورس ثابت v150 ساخته و **فاقد امضا** است. برای به‌روزرسانی همان برنامه موجود، حتماً با کلید امضای سازگار آن نسخه امضا شود.

چنانچه `GITHUB_TOKEN` در تنظیمات Actions اجازه `contents: write` نداشته باشد یا شاخه main در آینده به قوانین Pull Request محدود شود، ذخیره خودکار در GitHub متوقف می‌شود؛ موفقیت انتشار در پنل Cloudflare **به‌تنهایی** اثبات آرشیوشدن نیست. گزارش اجرای Workflow را کنترل کنید. هیچ رمز پنل، توکن GitHub خصوصی یا کلید انتشار APK داخل این آرشیو نگهداری نمی‌شود.

پخش جلسات و کلیپ‌ها همچنان از لینک اینترنتی صورت می‌گیرد؛ فایل‌های اصلی صوت/ویدئو در APK بسته‌بندی نمی‌شوند. کاورهای انتشار یافته در آرشیو و APK بعدی قابل‌بسته‌بندی هستند.
